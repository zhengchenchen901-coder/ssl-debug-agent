# 日志查询功能评估

评估日期：2026-10-13（北京时间）。范围：当前仓库、已安装插件运行包、当前会话中 test-server 的日志查询实测。未修改插件实现或服务器配置。

## 判断

项目映射、远端过滤、流式解压和有界执行的方向合理，已能明显改善日志读取效率。但精确接口过滤存在确定的漏查问题，归档结果的“最新”顺序也不可靠。目前适合辅助排查，尚不能直接依赖它自动回答“某餐厅某一天的完整接口调用”。

## 已确认的代码问题

### P1：精确 route 过滤不支持已部署的新日志字段

位置：agent/log-query-remote.js:119–125。

解析器只读取 inner.path / inner.route，而真实 API 日志使用 request_path / route_template。method 与 timestamp 可以解析，但 route 为 undefined，精确过滤静默丢弃记录。

本地复现：同一条新格式日志，用 route 查询得到 matchedLines=0、complete=true；用 contains 查询得到 matchedLines=1。现有测试的构造器只生成旧格式 path，因此未暴露问题。

建议：兼容新旧字段；区分具体请求路径和路由模板，明确 route 的语义。记录筛选字段缺失数量，避免将“无法解析”误读为“没有请求”。

### P2：归档限额下保留的是成员顺序末尾，而非时间最新记录

位置：agent/log-query-remote.js:131–146、207–208、395–399。

不同 tar 成员共用 records 缓冲；超过 limit / maxBytes 时移除较早进入缓冲的记录。归档成员顺序不保证与日志时间一致。

本地复现：归档先放 23:00 的记录、再放 01:00 的记录，limit=1 返回 01:00；即使已有 23:00 的更新记录也会被丢弃。matchedLines=2、outputTruncated=true，计数与排序是两个独立问题。

建议：对可解析时间的记录进行跨成员有界排序，或明确返回的是扫描顺序并提供独立的时间排序能力。补充多成员顺序交错、gzip/tar latest 场景测试。

## 实测暴露的产品与运行问题

| 项目 | 实测/代码证据 | 建议 |
| --- | --- | --- |
| 完整性警告 | test-server 项目查询反复返回 ERR_DIR_CLOSED，扫描未截断仍 countsAreComplete=false。Node 14/22 本地同样查询无此警告；根因未确认 | 核查实际远端 Node 版本与目录迭代关闭行为；区分无害关闭提示与影响覆盖的错误 |
| 预算后续扫 | 默认扫描 32 MiB；本次 info 日志约 162 MB，必须调大预算。前一天归档 info 内容约 325 MB，超过 256 MiB 上限后只能手动拆成员 | 返回未扫描文件/成员、字节位置和可续查游标；保持预算限制 |
| 日期与时区 | date 是文件名日期；北京时间一天跨两个 UTC 文件日期，调用方必须自行选两天 | 增加业务日期+时区的查询入口；区分文件日期与记录时间 |
| 餐厅归属 | 该接口的请求/响应无餐厅标识，account_id=null；90 次空 booking_order 请求无法确认属于 KEG8V | 后端在认证解析后写入餐厅标识，再提供结构化餐厅过滤；插件无法补回日志未记录的信息 |
| 延迟可解释性 | 一次扫描约 162 MB，远端处理 2.530 秒，但调用 durationMs=40.128 秒、executionMs=40.127 秒、queueMs=0。另一次相近扫描远端 2.757 秒、调用 4.658 秒 | 细分助手启动、首字节、SSH 输出传输、返回处理耗时；不能仅按远端耗时承诺查询速度 |
| 返回负载 | 同时返回 records[].text 与 content，内容重复；默认还携带较长 memory | 提供精简响应模式、字段投影和请求/响应聚合，减少模型侧解析成本 |

日期+时区的本地复现：用同样时间条件并限制单个 UTC 文件日期，会漏掉前一天 17:00Z 的记录。这符合当前 date 的文件名语义，是接口易用性缺口，并非时间比较错误。

预算截断已明确报告 scanTruncated/countsAreComplete，这是正确设计。缺少续查游标导致人工重复解压与扫描，不应通过取消预算来解决。

## 做得好的部分

- 实例与项目映射持久化，不需要扫描整台机器；映射不扩大路径权限。
- 搜索在远端完成，只传回有界结果；gzip/tar-gzip 流式解压，不创建解压产物。
- 路径规范化、符号链接检查、归档成员限制和固定助手避免任意 shell 执行。
- 文件数、扫描量、解压量、行大小、输出量、超时和后台并发均受限。
- 返回源文件、成员、行号，以及扫描截断/输出截断/计数完整性字段，证据比普通 tail/grep 更容易追溯。

## 验证

本轮执行了 14 项日志查询测试、2 项 HTTP 日志/映射测试、1 项 MCP 暴露与转发测试，共 17 项通过。另执行本地临时样例，复现新格式 route 漏查、归档结果时间倒置，以及文件日期和北京时间范围的差异。没有新增仓库测试或修改实现。

仓库与已安装缓存的 runtime-manifest.json 声明相同 runtimeId；本轮未重新校验整个运行包散列，也未核对运行中 Manager 的 runtimeId，不能据此排除全部部署差异。

建议先修精确 route 与归档排序，再定位 ERR_DIR_CLOSED 并补足续查能力。餐厅定位需要同时改进后端日志上下文。

# MongoDB 通用批量性能验收

## 环境与口径

- 执行日期：2026-09-29
- 数据库：本地 Docker `mongo:4.2.24` 单节点副本集，仅含本次合成数据
- MongoDB Node.js 驱动：6.18.0
- Agent 默认批次：500 个操作；并发：2
- 数据库请求口径：固定 helper 对 MongoDB Collection API 的调用数；不含连接握手、事务协议命令、SSH 往返或本机种子数据写入
- 日志口径：任务目录实际文件总字节；另列最大单批回滚日志
- 计时口径：分块上传、准备、执行、复核、回滚的本地端到端耗时；不代表生产网络或生产集群

## 旧流程对照口径

完整旧流程未在本轮重放，所以没有可比的旧流程耗时或线级请求遥测，也不据此声明提速倍数。按现有普通事务的 20 操作上限计算，跨集合任务至少需要 1,886 个业务事务，668 个单操作更新至少需要 34 个业务事务。以现有普通修改 helper 的准备与提交读写路径逐项计数，前者约 150,832 次、后者约 2,672 次 Collection API 调用；这是算法容量估算，未计连接握手、事务协议消息，不能冒充实测。

本轮新引擎的集合调用数包含准备、复核和回滚，因此与旧业务提交阶段的估算不是完全相同的测量边界。若需要严格的旧新时延对照，应在同一硬件、同一 MongoDB 版本和同一确认工作流下重放旧工具；不能用此本地单节点数据推算生产收益。

## 结果与限制

- 新引擎两组输入均未超过每任务 40 MiB 的输入限制，回滚日志按单批分别低于 8 MiB。
- 跨集合任务执行后任务目录约 40.1 MiB；任务总日志空间会高于输入限制，因为还包括前镜像、后镜像摘要和批次文件。
- 两项测试都在本地单节点副本集完成；尚未测量多节点复制延迟、生产 SSH 网络、磁盘压力或并发业务负载。
- 数据为生成的 ID 和数值，没有使用会员、电话号码或生产记录。

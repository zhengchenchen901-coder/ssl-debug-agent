# 沙盒文件边界加固：2.3.1

采用用户选择的第一种方案：服务器保留任务正文、进度、日志和回滚副本；内容是否与业务任务相关，由后续插件与实例之间的护栏处理。代码样式的文本仍可作为合法业务数据保存，但存储记录不能作为模块、脚本或 shell 输入执行。

本轮修改批量任务沙盒的文件入口：

- 块、业务单元、操作和动作请求采用封闭字段结构，拒绝额外的文件路径、文件名和内容上传参数。合法业务字段保持原有类型能力。
- 只接受插件生成的固定 JSON/JSONL、租约与锁文件路径；校验根目录/任务目录的 canonical 路径、当前 SSH 用户归属、0700 目录和 0600 文件权限。符号链接、硬链接和未知文件名被拒绝。
- JSON 读取和事件追加检查实际打开的描述符，使用 Linux O_NOFOLLOW，并验证普通文件、单链接、属主、权限和大小。JSON 只作数据解析。
- 文件写入使用专用目录的容量锁重新计数：2 GiB 数据预算、额外 64 MiB/1024 条控制空间、200 个新任务目录、20000 条普通文件记录；单任务普通记录 1950 条，控制记录预留 50 条；单事件日志 8 MiB。额度包括原子替换所需的临时空间。到限额时保留已有记录并报错，不自动删除恢复数据。
- 过期任务清理的文件删除与写入使用同一容量锁。清理仍要求已有完成状态、保留期限和确认哈希；旧业务库中的收据不迁移、不清理。
- capabilities 和数据库技能公布规则与错误处理。MCP 工具名、参数和基础启动/转发协议保持不变；未知请求字段现在显式拒绝。

限额针对逻辑文件大小和条目数，不替代操作系统磁盘配额；预留控制空间不能保证磁盘满或异常历史任务时所有恢复操作都可完成。统计容量增加文件系统扫描开销。沙盒账户配置计划和普通数据库变更日志仍采用各自已有的固定路径与权限规则，本轮新增目录总量限制针对批量任务沙盒目录。此方案不是 SSH 进程的容器隔离，也不限制其他独立授权的管理入口。

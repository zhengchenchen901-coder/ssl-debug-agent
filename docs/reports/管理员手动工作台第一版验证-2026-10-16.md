## macOS 认证组件准备修复（2026-10-16）

真实 Manager 环境中 xcrun 的子进程误选了 Intel 架构，无法加载只含 ARM 切片的 libxcrun.dylib；机器本身已安装有效 Command Line Tools。独立 ARM 进程编译通过不足以覆盖实际插件启动环境。

Apple Silicon 上对编译器查找、Swift 编译、helper 可用性检查及实际认证明确使用 `/usr/bin/arch -arm64`。即使 Node 报告 arm64，仍固定这些子进程的架构；Rosetta Node 通过硬件检查选择原生架构。缓存按源文件和原生架构区分。

注册界面先通过受本地 token 保护的 prepare-owner 接口构建并检查组件，成功后启用提交按钮。准备阶段不会弹出认证窗口，不产生 nonce 授权，不创建管理员。编译器缺失、编译失败、超时和安装失败使用不同错误码。

最终回归：Agent 279 通过、2 跳过；插件 63 通过、2 跳过；浏览器注册与真实 SSH 流程通过。已更新当前安装并重载 Manager，实际 prepare-owner 返回 HTTP 200、prepared=true，进程与目标架构均为 arm64。当前组件已编译并可用，系统密码输入仍由用户本人完成。

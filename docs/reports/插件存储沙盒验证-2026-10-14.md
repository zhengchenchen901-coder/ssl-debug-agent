# 插件存储沙盒验证（2.3.0）

实现保留上一轮 TTL 修复。新 v2 任务把技术凭据写入同一 MongoDB 部署的专用数据库，业务修改与凭据使用同一个事务。旧 v1 计划哈希和凭据 ID 保持兼容，按原业务数据库恢复、重试和回滚。没有迁移或删除真实实例中的旧集合，也没有初始化生产沙盒。

新增本机/远端沙盒容量检查、脱敏日志导出以及准备后确认的过期任务清理。管理接口只接收实例/任务 ID；远端管理必须使用相同 MongoDB 连接端点上的独立配置和仅限专用数据库的账户。有效权限含业务或全局访问时拒绝管理。清理必须满足终态、无活跃租约、回滚期加 24 小时结束、路径无链接/未知文件及预览哈希未变化；旧业务库的凭据集合不在清理权限内。文件目录继续沿用原有专用位置，保证旧任务可找回；本机当前审计日志不被清理。

## 验证证据

- Agent 完整测试：239 通过；真实 MongoDB 集成在默认测试中跳过后另行运行通过。
- 插件完整测试：48 通过；Windows 安装测试和固定 4343 端口测试因当前环境跳过。
- 新增生成式远端 helper 行为测试，覆盖同一 session 的跨库原子提交、凭据插入失败回滚、提交回执丢失后防重复执行、新旧任务回滚、计划存储绑定、管理角色越权、保留期限、旧记录保护、预览冲突与符号链接拒绝。
- 另外启动了独立、仅监听本机随机端口、开启认证的 MongoDB 4.4.30 单节点副本集。用 MongoDB Node 驱动 3.3.4 运行跨库提交/回滚和真实 RBAC 集成测试：沙盒管理账户可以查看技术日志，但读取业务集合被服务器以 Unauthorized 拒绝。该容器已清理，既有本地服务和远端实例未被操作。
- 在无真实实例的隔离配置下，diagnose 初始化成功、注册 36 个 MCP 工具、HTTP Agent 验证通过。预编译运行包已重建；发布前还需要按 README 初始化专用库并配置管理账户。

## 事务位置对照测试

仅比较凭据位于业务库和同部署专用库的事务耗时。每个事务更新 200 条记录并插入一条凭据；预热两轮，各测 12 次，交替顺序。其他条件一致。

| 布局 | 中位耗时（毫秒） | 样本最大耗时（毫秒） |
| --- | --- | --- |
| 业务库内技术集合 | 2.163 | 2.575 |
| 专用数据库内技术集合 | 2.055 | 2.392 |

该小样本未显示明显性能损失，不能推导专用库更快或生产环境没有开销。测试不包含不变的 SSH/文件日志成本，也不覆盖分片跨节点、生产并发、真实日志体积或管理扫描的最坏情况。多分片部署仍需要单独验收。Windows ACL 实机验证不由本次 macOS 测试替代。

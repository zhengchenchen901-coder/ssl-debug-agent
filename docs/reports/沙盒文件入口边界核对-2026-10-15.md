# 沙盒文件入口边界核对

用户目标：插件专用存储不得成为向服务器投放无关文件或程序的通道。

当前源码核对：

- 批量任务接口接受结构化数据库操作，校验集合白名单、操作类型、标识符和单任务大小；未提供调用方指定任意落盘文件路径或文件名的通用上传接口。
- 任务文件由插件生成固定名称，以 JSON/JSONL 保存，目录 0700、文件 0600；记录读取使用 JSON.parse。已核对的批量与沙盒管理运行时没有把这些记录交给 eval、Function、shell 或动态模块加载执行。
- 固定 MongoDB 收据只负责批次执行凭据；操作正文、修改前数据等主要落在服务器任务目录。批量准备阶段已经写入这些文件，业务提交确认发生在之后。
- 业务字段允许文本和部分 Extended JSON 数据，因此合法格式的数据仍可能包含任意文本/二进制内容。不能依靠文件后缀、JSON 格式或“代码识别”保证其语义与任务相关。
- 目前有单块、单文档、单任务大小上限；未找到覆盖整个实例存储的统一磁盘配额与未确认任务总量控制。管理扫描上限不能替代写入配额。

需要确认的存储政策：

1. 保留远端任务正文与回滚数据：继续提供服务器任务恢复能力，强化封闭输入格式、路径/归属/文件类型验证、非执行原则、任务授权绑定、总量配额与到期管理。这种政策禁止通用上传，但仍允许必要的业务文本作为任务数据保存。
2. 服务器只保留最小执行凭据：任务正文、日志和回滚副本均保存在本机，服务器上不持久化这些内容。需要重新设计现有批量准备、恢复与回滚流程；数据库操作数据在执行时仍须传递给目标数据库。

此核对阶段仅检查源码，未上传测试载荷、修改远端文件、关闭功能或删除已有记录。随后用户选择第一种存储政策；实现与验收见《沙盒文件边界加固验证-2026-10-15.md》。

# 项目日志查询改造与生产验证

日期：2026-10-12，日期与相对日期按北京时间解释。

## 已实现

- 持久化实例 → 项目 → 项目根目录/日志目录映射，dashboard 与 MCP 均可配置。映射不会扩展原有路径权限，项目查询立即使用更新后的映射。
- latest：读取纯文本文件尾部小块，满足所需行数后停止。默认查询最新的一个候选文件。
- files：仅枚举项目配置的日志目录，通过文件名、日期/日期范围选择文件，支持文件分页，不递归扫描整台服务器。
- search：在远端匹配字面关键词、精确 JSON 接口路径、HTTP 方法、级别及带时区的时间范围，只回传有界结果。支持 message 中嵌套的 JSON。
- members：在远端流式列出 tar.gz/tgz 成员，支持前缀、分页与返回大小限制。现有归档成员工具也使用此实现。
- gzip/tar.gz 在远端流式解压，不创建临时目录、脚本文件或解压文件；指定成员读完后提前停止。拒绝成员路径穿越和链接内容读取。
- 返回来源文件、归档成员、行号或从末尾计数、扫描字节、解压字节、匹配/返回数量及覆盖状态。截断、文件变化、警告均显式返回。输出截断与扫描不完整分别报告。
- 搜索、压缩与项目查询受每实例一个后台通道、文件数、目录项、行大小、扫描量、解压量和执行时间限制。默认内容扫描 32 MiB、解压 1 GiB，最大分别为 256 MiB、2 GiB。
- 新助手单独转译为远端 Node 12.12+ 可执行代码；本地 Agent 仍使用 Node 22。参数作为 JSON 数据传入固定助手，不拼接用户 shell 命令。
- 现有 read_log 保留按时间先后排列的内容格式，直接使用新的远端执行路径。

测试服务器也验证了最新记录读取约 2.4 秒。验证结束后 default 与 test-server 均为 running/healthy，未发生 SSH 重连，无排队或未结束操作。

## 生产存储评估

生产根盘为 40 GiB，使用率 72%，可用约 11 GiB；昨天归档约 380 MiB，现有最大归档约 504 MiB。未测量所有归档的完整解压体积，不能凭压缩大小保证临时解压的峰值占用。

假设最大归档解压后为压缩大小的五倍，一份临时展开约占 2.5 GiB，两份并发约占 5 GiB，另有持续日志增长及异常清理残留的占用。删除临时目录只能回收查询结束后的空间，不能消除峰值磁盘写入与容量需求。因此正式服默认采用流式解压，不落盘；CPU 与读取 I/O 成本仍通过并发和预算限制控制。

# Remote Debug Agent 插件安全审计

审计日期：2026-10-14（Asia/Shanghai）。仓库提交：`9412a8e`。

结论：存在明确的安全边界缺口，需要优先修复本地接口鉴权、命令参数校验、SSH 主机身份校验，以及 TTL 索引的数据删除风险。已有白名单、超时、事务、计划哈希和回滚机制有价值，但不能据此认定插件已经具备完整的安全隔离。

- 使用 Node 22.23.3 运行 82 项相关现有测试，全部通过。测试范围包括命令安全、HTTP 服务、命令审批、MongoDB 查询/变更/批量任务及 SSH 连接管理。
- 额外验证全部使用临时目录、假敏感信息、临时监听端口和 SSH mock。没有连接实际远程服务器，没有修改真实数据库，没有读取真实私钥或口令。SSH 中间人和 TTL 删除的结论来自代码及官方语义，未进行真实攻击或数据删除实验。
- 对生产依赖运行 `npm audit --omit=dev --json`，并核查相关公告。扫描命中不直接等于当前应用路径可利用。

**F1：本地管理接口缺少鉴权**

位置：[Manager 中间件](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/server.js:1849)、[实例创建/修改](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/server.js:1980)、[Worker 中间件](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/server.js:479)。

两种服务都没有请求身份验证，也没有 Host/Origin 校验。配置固定监听 `127.0.0.1`，因此不能描述为直接暴露在公网；但任何能连接本机端口的进程都能请求这些接口。Manager 的配置修改、实例启动/刷新、数据库和命令执行代理也处于这个边界内。

隔离实验中，不携带认证信息、携带外部 Host/Origin 的请求可以创建启用命令草稿权限的实例，返回 201；预编译 Worker 的 `/run` 返回 200 并进入 SSH mock。Manager 在默认 manual 生命周期下，对外部 Origin 的 `text/plain` POST `/api/shutdown` 返回 202 并触发 mock 关闭动作。

浏览器的 CORS、预检和本地网络访问规则会影响网页攻击是否成立；本次没有证明所有浏览器都能跨站执行完整攻击链。但服务端没有防护这一点已经确认，且普通本地进程不受浏览器规则限制。没有 Host 校验也留下 DNS rebinding 的攻击条件。

建议：在 Manager 与 Worker 都增加认证，Worker 使用每次启动生成的独立凭据并通过 IPC 交给 Manager；限制 Host/Origin，为 Dashboard 的修改请求增加 CSRF 防护；将配置权限变更与普通读取接口区分。Unix socket 的访问权限、Windows named pipe 的 ACL 也可用于限制本地客户端。鉴权仍需结合本地凭据保护，不能承诺抵御已经完全控制当前用户账户的恶意程序。

**F2：命令路径校验忽略不包含斜杠的参数**

位置：[validatePathArguments](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/security.js:350)、[执行校验后的命令](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/server.js:545)。

校验逻辑跳过所有不含 `/` 的 token，只要求至少出现一个合法绝对路径。因此下面的形式可以通过：

```text
cat /var/log/public.log .env
```

`.env` 被当成普通 token，既不加入远程 canonical path 校验，也不被拒绝。远程命令会根据工作目录读取该文件。即使 `.env` 在允许根目录之外，只要 SSH 账户有读取权限，就可能返回其内容。

临时实验只允许 `<fixture>/allowed`，将假 `.env` 放在该目录外、作为命令工作目录中的文件；校验通过，实际 `cat` 返回了假敏感信息。当前运行包的 `/run` 同样允许该形式进入 SSH mock。无需开启数据库写入或命令草稿权限。

建议：为每个允许的命令定义参数语法，明确区分选项、选项值、搜索表达式和文件参数；所有文件参数必须为允许的绝对路径。`cat`、`tail` 的所有文件操作数都应检查。对于递归读取或跟随链接的选项，另行限制遍历范围。本次在 macOS 上没有复现递归 grep 跟随链接的读取，因此没有把它作为已经验证的问题。

**F3：SSH 不验证服务器主机密钥**

位置：[connectionOptions](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/ssh-connection-supervisor.js:84)。

连接配置传入 host、port、username、privateKey、passphrase 和连接限时，但没有 `hostVerifier`、固定主机指纹或 known_hosts 校验。已安装依赖 ssh2 的密钥交换实现明确在没有 verifier 时接受主机密钥。

控制目标地址、DNS 或网络链路的攻击者可能冒充目标服务器，接收插件发送的命令和助手脚本，伪造日志、查询和变更结果；脚本输入本身可能带有业务数据。这里并不意味着 SSH 私钥会以明文发送给攻击者，私钥认证与服务器身份验证是不同的步骤。

建议：配置经过可信渠道核对的主机密钥指纹，并在所有连接与重连中强制匹配；密钥变化应停止连接并明确提示，不能静默自动接受。

**F4：TTL 索引绕过“有界文档变更”的数据影响范围**

位置：[索引风险分级](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/mongodb-mutations.js:81)、[TTL 参数校验](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/mongodb-mutations.js:675)、[索引预览计数](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/mongodb-mutations.js:1144)、[索引回滚](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/mongodb-mutations.js:1590)。

`createIndex` 接受 `expireAfterSeconds: 0`，普通非唯一 TTL 索引被标为 `medium`，计划的 `affectedCount` 仅记为一个索引，未估算将过期的文档数。回滚只删除新建索引，未保存和恢复 TTL 后台删除的文档。

在包含已过期日期的业务集合上执行该计划后，MongoDB 的 TTL 后台任务可以删除大量记录。这些删除不受普通文档变更的 `_id` 范围或 `maxAffectedDocuments` 限制。索引删除能够阻止后续过期清理，但无法找回已经删除的数据。MongoDB 官方也提示，新建 TTL 索引后可能有大量文档满足删除条件：[TTL Indexes](https://www.mongodb.com/docs/manual/core/index-ttl/)。

纯本地校验实验确认 `key: {createdAt: 1}`、`options: {expireAfterSeconds: 0}` 会被接受，并返回 `riskLevel: medium`。实际风险需要启用数据库写入、允许目标集合并执行已确认的计划；本次没有执行真实索引创建。

建议：业务集合的 TTL 索引默认禁止，或提供独立能力开关、明确的不可恢复数据删除提示、高风险分级及过期文档预估。技术 receipt 集合的 TTL 可以单独定义严格策略，避免通用禁止影响既有批量任务设计。

**F5：确认短语和计划哈希不能证明用户授权**

位置：[草稿执行入口](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/server.js:727)、[claimDraft](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/approved-commands.js:261)、[数据库确认检查](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/mongodb-mutations.js:1769)。

草稿执行只验证已开启权限、草稿状态、时效、哈希及 `使用命令` 这个固定字符串，不要求存在已保存的审查结果。创建草稿的调用方会收到 draftId 和哈希，也可以自行填写确认短语。数据库执行工具的 `确认执行` 同样是请求字段，不能作为独立的人工授权证明。

在预编译 Worker 的隔离 HTTP 实验中，先生成只包含 `printf FIXTURE_ONLY` 的草稿，再直接执行，没有调用 reviewer；请求返回 200，命令进入 SSH mock。此功能默认关闭，因此这不是默认配置下直接开放的任意命令执行，但它依赖客户端/模型遵守 skill 流程。命令哈希提供内容绑定与防篡改，不能提供用户身份或同意证明。

建议：将审查结果存入服务端状态；对需要人工批准的执行，用可信 UI 或宿主审批机制产生有时效、绑定具体实例及计划哈希的一次性授权。审查拒绝后仍允许人工覆盖时，应单独记录明确的覆盖授权，而非由模型自行传入固定短语。

**F6：敏感信息脱敏与本地文件保护不完整**

位置：[stdout 事件](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/server.js:549)、[status 暴露最近事件](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/server.js:503)、[失败命令审计](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/server.js:593)、[实例中的 passphrase](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/instance-registry.js:327)、[实例文件保存](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/instance-registry.js:554)、[审计文件创建](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/audit.js:74)。

- 命令 stdout/stderr 的事件仅截断、不脱敏。假 `TOKEN` 输出能从无鉴权的 `/status` 最近事件中读到，`/events` 也提供事件订阅。
- `/run` 对被拒绝命令保存原始字符串前 256 字符。假 `curl --token FAKE_AUDIT_SECRET_ONLY` 虽被拒绝，token 仍进入审计文件。
- 实例 passphrase 保存在 JSON 中；保存实例与创建审计文件没有显式指定 owner-only 权限。隔离实验中，在当前 macOS 默认 umask 下两个文件为 `0644`。这不是对实际生产文件权限的断言，也没有验证 Windows 部署的继承 ACL。

建议：审计和事件统一脱敏；默认只保留输出长度、状态等元数据，对调试输出限制访问与保留时长；口令优先使用系统凭据存储，配置目录采用 owner-only 权限/ACL，并修复既有文件权限。

**F7：数据库读取范围取决于远程应用账户，而非独立读取策略**

位置：[读取配置规范化](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/mongodb.js:96)、[读取请求库与集合选择](/Users/zhengchenchen/od-projects/ssl-debug-agent/agent/mongodb.js:241)。

当前 `allowedDatabases` 和 `allowedCollections` 用于写入策略，读取配置规范化不会保留或检查这些列表；读取请求也能覆盖配置中的默认 database。隔离实验传入仅允许一个数据库和一个集合的列表，查询校验仍接受其他格式合法的数据库和集合。

这是读取权限范围设计，而非已经证明绕过 MongoDB 自身 RBAC。真正能读到什么仍由应用连接 URI 的账户权限决定。但“只读”和单次 500 条上限并不限制数据敏感程度，也不限制多次分页读取。聚合中的跨集合操作还需纳入读取策略。

建议：提供单独的读取数据库/集合白名单及敏感字段策略，校验 `$lookup`、`$unionWith` 等跨集合读取；优先使用专门的只读诊断账户，避免继承业务应用账户的全部权限。

**已有有效防护与结论边界**

已有命令白名单和 shell 控制字符拒绝、SFTP canonical 路径检查、超时与响应大小限制、MongoDB 危险操作符递归拒绝、写入库/集合白名单、事务和原值冲突检测、草稿哈希及一次性状态检查。Dashboard 创建文本节点而非直接将返回数据拼成 HTML，本次未发现可确认的直接 HTML 注入路径。

本次是代码审计和隔离验证，不是对生产环境的完整渗透测试。没有检查真实目标的 SSH 账户权限、数据库 RBAC、实际文件 ACL、备份和浏览器访问策略，也没有发现或证明当前系统已经遭到攻击。

修复顺序建议：先封住 Manager/Worker 访问边界，同时修复文件参数校验与 SSH 主机密钥验证；随后限制业务 TTL 索引和强化可信授权，再完善脱敏、文件保护、读取权限及依赖升级。新增回归测试应覆盖本报告已经复现的攻击输入，并对预编译运行包验证，避免只修源码而遗漏发布产物。

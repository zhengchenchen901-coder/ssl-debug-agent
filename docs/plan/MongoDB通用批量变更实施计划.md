# Remote Debug Agent MongoDB 通用批量变更执行计划

## 一、目标与实施边界

在 `ssl-debug-agent` 仓库实现“**通用批量工具＋现有数据库 Skill**”，解决大量不同值更新、跨集合新增与更新、长任务续跑及安全回滚的问题。

已确定的行为：

- 使用受控后台任务，客户端断开后继续执行已提交的固定计划。
- 遇到冲突或失败，暂停整个任务的新批次调度，保留已成功结果。
- 在目标数据库增加专用技术集合，通过同事务回执识别提交结果，防止重复执行。
- 保留现有单条修改、普通事务、导入和索引工具的接口兼容性。
- 本次建设不重新执行此前的会员、VIP 或积分同步，不新增业务管理页面。

实施以当前已有的批量导入和 BSON 编解码改动为基础。先核对未提交差异，保留既有工作，不将无关 Dashboard 改动一起发布。当前 49 项 Mongo 相关测试通过，作为回归基线。

## 二、工具接口与批量执行引擎

### 1. 新增接口

以下工具统一使用 `remote_debug_mongodb_` 前缀：

| 工具 | 职责 |
|---|---|
| `prepare_bulk_storage` | 准备技术集合、索引和持久化日志目录的初始化计划；使用现有执行工具提交 |
| `prepare_bulk` | 接收分块输入，校验范围、原值和业务单元，生成批次及不可变计划 |
| `execute_bulk` | 根据 `jobId`、`planHash` 和确认短语启动后台任务，立即返回任务标识 |
| `get_bulk_job` | 查询进度、批次状态、错误、回滚期限和分页差异预览 |
| `list_bulk_jobs` | 分页查询任务，便于断线或重启后找回 |
| `control_bulk_job` | 暂停或恢复同一固定计划 |
| `rollback_bulk_job` | 明确确认后，逆序回滚已提交批次 |

HTTP 接口放在 `/mongodb/bulk/*`，继续经过现有 Manager、Worker、实例路由、白名单和审计边界。Skill 不直接调用内部 HTTP，也不通过脚本或 Mongo Shell 绕过这些接口。

### 2. 输入与原子性

批量输入按“业务单元”组织，每个单元具有稳定 `unitId` 和操作列表。例如：

- 更新一名会员的累计积分：一个单元包含一条更新。
- 补绑定 VIP：一个单元同时包含 Customer 更新和 CustomerPrivate 新增或更新。

V1 支持：

- `insertOne`：必须提供明确 `_id`。
- `updateOne`：必须限定明确 `_id`，只允许 `$set`、`$unset`、`$inc`。
- 更新必须携带原值条件，明确区分“字段不存在”和 `null`。
- 同一个业务单元不可拆分；一个事务可容纳多个业务单元。
- 同一任务中，同一个“集合＋文档 ID”只能出现一次，保证批次之间互不依赖。
- 一个任务只写一个数据库，可以涉及多个已获准集合。

V1 不支持任意脚本、聚合更新、自动 upsert、业务物理删除，以及依赖前一操作返回值的动态操作。数组修改继续采用“保留原数组、构造目标数组、原值校验后替换”的方式。

### 3. 固定默认限制

| 项目 | 默认或上限 |
|---|---|
| 每个业务单元 | 最多 20 个操作 |
| 每次上传 | 最多 10,000 个操作、4 MiB |
| 单个任务 | 最多 100,000 个操作、40 MiB 输入 |
| 每批文档数 | 默认 500，实例可配置，硬上限 2,000 |
| 每批操作输入 | 最多 512 KiB |
| 每批回滚日志 | 最多 8 MiB |
| 后台并发 | 默认 2，实例配置最高 4 |
| 回滚保留期 | 默认 7 天 |

按实际前镜像大小和后镜像摘要空间进一步拆批；不得拆开业务单元。单个单元超过限制时，在准备阶段拒绝，不能先写入再发现无法保存回滚数据。

上传分块必须有顺序号和内容摘要。相同分块重复提交返回已有结果，内容不同则报冲突；全部分块准备完成并显式结束上传后，才生成可执行的最终 `planHash`。

### 4. 真正减少数据库往返

- 按集合批量读取目标、校验前镜像、执行 `bulkWrite`、读取结果。
- 同一事务内依次执行各集合的批量操作，不在事务内部并行调用数据库。
- 禁止退化为逐文档“查询—更新—查询”循环。
- 普通事务的 20 操作限制保持不变；新批量引擎使用独立、明确的限额。
- 分别记录匹配数、实际修改数、新增数和未变化数，不能把匹配成功都统计为修改成功。

## 三、一致性、后台运行与故障恢复

### 1. 修复 BSON 兼容问题

统一复用并完善 `agent/mongodb-codec.js`：

- 修复导入路径仍强制依赖原生 EJSON 的问题；不能只删除检查后使用普通 JSON。
- 优先使用驱动原生 EJSON，旧驱动使用受测试覆盖的 BSON 构造器兼容路径。
- 快照与哈希使用保留类型的编码，覆盖 ObjectId、Date、整数、浮点数、Long、Decimal128，以及受支持的二进制、时间戳等类型。
- 对不能无损编码、解码的值，在准备阶段明确拒绝。
- 新日志采用版本化格式；旧日志继续按原版本读取和回滚。
- 保持现有只读查询的默认输出格式，避免影响现有调用方。

### 2. 技术集合与持久化日志

默认技术集合为 `__remote_debug_bulk_receipts`，仅保存任务身份、计划摘要、租约和批次回执，不保存完整业务前镜像。

- 初始化必须单独准备、展示和确认，不在普通批量任务中偷偷建集合或索引。
- 技术集合必须纳入实例配置许可。
- 每批业务变更与唯一批次回执在同一 MongoDB 事务中提交。
- 回滚时，恢复业务数据与回滚回执也在同一事务中提交。
- 回执保存至回滚期限后至少 24 小时；保留最小任务终态记录，禁止过期任务 ID 被当作新任务重放。
- 前镜像使用持久化目录，默认 `/var/lib/remote-debug-agent/bulk-jobs`，由实例配置指定；目录 `0700`、文件 `0600`，不回退到临时目录。
- 权限不足、日志空间不足或无法保证原子落盘时，在业务写入前停止。
- 初始化回退不自动删除技术集合、日志目录或已有回执；关闭批量能力即可停止使用。

业务唯一性仍依赖数据库约束。例如 CustomerPrivate 按客户和集团唯一时，预演必须检查对应唯一索引；缺失时单独提出索引预案，不把 `_id` 不重复误当作业务不重复。

### 3. 后台调度与暂停

任务由 Worker 持有独立生命周期，不绑定启动请求的取消信号。

- 状态包含：准备中、可执行、运行中、暂停中、已暂停、复核中、已完成、回滚中、已回滚。
- 调整当前 SSH 调度器，避免 `bulk` 继续被普通后台任务默认单槽限制。
- 批量任务使用独立并发预算，同时保留控制通道及至少一个交互通道。
- 返回实际生效的并发数、运行批次和排队数。
- 同一实例同时只允许运行一个批量任务；第二个启动请求明确返回忙碌。
- 暂停或发生错误时，停止派发新批次，让已开始的事务结束，再汇总真实结果；不强杀正在提交的事务。
- Manager 或 Worker 重启后恢复任务记录，默认暂停，核对日志和回执后才能续跑。

### 4. 断线、冲突与回滚

- 提交前重新校验原值和完整前镜像，任何不一致都使整个批次失败。
- 连接断开后，从主节点查询匹配的事务回执；有回执才能确认该批已提交。
- 没有回执不能直接宣称“未提交”。恢复时仍使用相同批次身份、唯一回执键和原值校验，保证至多成功一次。
- 不凭“当前数据看起来一样”推断任务拥有这些记录。
- 发生错误后暂停任务，不自动扩大范围、忽略冲突或重做成功批次。
- 回滚只针对本任务已提交批次，按提交顺序逆序执行；先检查当前数据仍等于本任务后镜像，冲突即暂停。
- 日志缺失、损坏或过期时，明确报告无法安全回滚。

成功写入与最终复核分别记录。只有全部批次成功且复核通过，才报告任务完成；复核发现后续业务变化时报告差异，不自动覆盖。

## 四、Skill 流程与实施顺序

扩展现有 `database-mutations` Skill，不新增一套重复的确认规则。批量细则放入其引用文档，主文件保留清晰入口。

统一流程：

1. **探测能力**：实例、数据库、集合许可、驱动与事务支持、技术集合、日志目录和有效限额。
2. **业务预演**：确定匹配规则、去重规则、保留对象、原值条件及禁止修改字段，生成差异清单。
3. **准备计划**：分块上传、检查全部批次与回滚能力，汇总影响数量和异常。
4. **执行授权**：复用用户对相同范围的明确授权，不逐批重复询问；范围或业务规则发生变化时重新确认。
5. **后台执行**：记录 `jobId`、最终哈希、进度、暂停原因和恢复位置。
6. **复核与交付**：验证修改字段、保护字段、遗漏、重复及业务例外，输出结果与回滚期限。

提供三个脱敏示例：按手机号匹配同步字段、仅补缺失字段、跨集合 VIP 绑定。集团 ID、电话号码和业务特例由调用任务提供，不写死在通用引擎中。

实施顺序：

- **阶段 1**：梳理现有改动，完成 BSON 兼容及旧工具回归。
- **阶段 2**：实现初始化、业务单元、分块预演、批量事务和事务回执。
- **阶段 3**：实现后台调度、状态查询、暂停续跑、冲突处理和回滚。
- **阶段 4**：更新 MCP、能力声明、Skill、示例及使用文档。

开始实施后，将本计划保存到目标仓库 `docs/plan/MongoDB通用批量变更实施计划.md`，后续直接更新该文档的实际结果。

## 五、测试、验收与发布

### 测试范围

- **范围校验**：错误实例、未许可集合、重复文档 ID、重复单元、非法更新字段和超限输入均被拒绝。
- **业务正确性**：只改目标集团，其他条目、积分流水和业务保护字段保持；缺失字段与 `null` 分别验证。
- **事务原子性**：Customer 更新成功但 CustomerPrivate 插入失败时，整个批次回滚；业务单元不能被拆分。
- **幂等与故障**：重复上传、重复执行、提交回复丢失、进程重启、暂停时仍有在途事务、多进程争抢、原值冲突及日志损坏。
- **回滚**：正常恢复、重复回滚、后续业务修改冲突、回滚回复丢失和期限过期。
- **BSON**：旧驱动和原生 EJSON 驱动分别验证类型与精度；不支持的值必须提前失败。
- **兼容性**：现有查询、单笔修改、普通事务、导入及索引工具全部回归。
- **真实集成**：使用本地 Docker 隔离副本集测试，覆盖现网旧版本组合与新驱动组合；不使用生产会员数据。

### 性能验收

用合成数据重放两类任务：

- 18,854 名会员，每人更新一个文档并新增一个关联文档。
- 668 名会员，各自更新不同累计积分值。

在不触发字节限制的测试数据下，第一类任务按默认每批 500 文档应不超过 **76 个事务**，避免再拆成约千个小事务。验证数据库请求数量按“批次×集合”增长，而非按每个文档增长。

记录旧流程与新流程的总耗时、数据库请求数、批次数、并发数和峰值日志大小，不对生产环境承诺未经实测的固定提速倍数。

### 发布与启用

1. 完成本地单测、真实副本集集成测试及故障注入测试。
2. 在隔离测试库完成全流程执行、暂停、断线恢复和回滚演练。
3. 按 **2.2.0** 功能版本同步 Agent、插件与清单版本，重建内置 runtime，核对 `runtimeId` 和工具注册。
4. 按仓库安装流程更新插件；不直接修改 Codex 插件缓存，不自动拉取或发布未审查的工作区改动。
5. 新批量能力默认关闭。生产启用前提供可审查的配置、技术存储初始化预案及测试报告。
6. 首次实际任务先执行一个小批次并复核，再放开默认并发。发生问题时暂停任务、关闭新能力；业务回滚使用对应任务日志，软件降级不能代替数据回滚。

最终交付包括：工具与类型定义、兼容性修复、后台执行引擎、测试、更新后的 Skill、操作文档，以及执行和回滚报告模板。


## 实施进度记录

- 2026-09-29：计划已归档；保留原有工作区改动，Dashboard 变更仍未提交。
- 阶段 1 完成：复核 BSON 编解码及导入路径；统一 native EJSON 与旧驱动 fallback，对精度敏感类型和不支持值增加覆盖。现有 MongoDB 查询、修改、事务、导入和索引测试纳入回归。
- 阶段 2 完成：增加默认关闭的批量存储初始化、稳定业务单元、顺序分块摘要、固定计划、按集合批量读取和 `bulkWrite`、事务回执、结果统计及事务内写回执。目标集合不存在、范围超限或前置值变化时在写入前拒绝或停止。
- 阶段 3 完成：增加 Worker 持有的后台执行、最多 4 个批次的独立并发预算、交互 SSH 通道预留、租约和多进程日志锁、断线回执识别、暂停续跑、批次复核及冲突保护的逆序回滚。关闭 `bulkEnabled` 后会阻止新任务和续跑，但仍可检查、暂停及显式回滚已有任务。
- 阶段 4 完成：新增 7 个 MCP 工具及对应 HTTP、实例代理和审计路由；扩展 `database-mutations` Skill、批量操作指引、脱敏示例及执行/回滚报告模板。Agent、插件与 runtime manifest 同步为 2.2.0；内置 runtime 已重建。
- 测试结果：最终 Agent 全套 175 项中 174 项通过、1 项跳过；插件全套 26 项中 25 项通过、1 项跳过。MongoDB 4.2.24 本地隔离副本集分别搭配 Node 驱动 3.7.4 与 6.18.0 完成跨集合事务、并发结束上传、提交回复丢失识别、复核和回滚验证。另有 HTTP 回归确认关闭新任务开关后仍能回滚已有任务。
- 性能实测：18,854 个跨集合单元按 500 个操作/批生成 76 批；668 个不同值更新生成 2 批。两类合成任务均完成执行、复核与逆序回滚。详情见 `docs/reports/MongoDB通用批量性能验收-2026-09-29.md`。
- 性能限制：旧流程未做完整重放，因此旧流程耗时和线级请求数未实测；计划文档仅记录普通事务 20 操作上限推算的批次数及 Collection API 调用估算，不声明提速倍数。新流程耗时只代表本地单节点副本集。
- 发布边界：未安装插件、未修改 Codex 插件缓存、未发布或部署，未启用批量能力，也未访问或修改生产数据。技术存储初始化与业务写入仍须按实例授权单独确认。

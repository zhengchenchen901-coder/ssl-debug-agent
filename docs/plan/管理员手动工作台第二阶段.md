# 管理员手动工作台第二阶段：MongoDB（2026-10-18）

工作台现在提供 SSH 和数据库两个入口。切换入口只隐藏面板，保留各自终端现场。数据库预览区包含库/集合目录、筛选、排序、游标分页、文档查看与编辑，以及只读索引查看；操作区启动真实 mongosh。服务日志与 Agent 建议仍属于后续阶段。

## 实例连接配置

实例管理新增 `manualMongo`，与自动业务连接 `mongodb`、沙盒管理 profile 分开保存。人工连接不会被复制到 Worker 环境，也不新增 MCP 工具、不修改自动查询/变更白名单。保存实例配置立即撤销原人工会话；自动 Worker 的配置重载沿用现有行为。

```json
{
  "manualMongo": {
    "enabled": true,
    "configPath": "/home/app/config.json",
    "driverPath": "/home/app/node_modules/mongodb",
    "configProfile": "manualAdmin",
    "uriKey": "mongodb.url",
    "database": "records",
    "nodePath": "node",
    "mongoshPath": "mongosh"
  }
}
```

`configPath`、`driverPath` 是当前实例 SSH 账户可读取的远端绝对路径。`configProfile` 是远端 JSON 的顶层分组名称，`uriKey` 可用点分隔访问该分组内的嵌套 URI 字段。允许复用已有配置文件/profile，但不会自动沿用业务或沙盒管理身份。URI 与密码只在远端进程读取，不保存在上述实例配置中，不发送给浏览器，不写入命令参数或审计。

默认库依次取人工配置 `database`、远端 profile 的 `database` / `databaseName`、URI 默认库。Node 与 mongosh 可以配置命令名称或绝对路径；路径通过 shell 引号保护，不接受附加命令参数。远端需要 Node 12+ 以及匹配该 Node 的、提供 BSON EJSON 的 MongoDB Node 驱动（建议 4.x 或更新）；实际版本兼容性需由部署环境核对。

数据库 shell 需要远端已有兼容的 mongosh。缺失时终端明确显示安装/路径配置要求，不模拟客户端、不自动安装、不降级为任意远端 Shell。它通过独立 SSH PTY 启动 `mongosh --nodb --norc --quiet --shell --eval …`，从进程环境读取远端 URI，启动后清除该环境字段。GUI 与 shell 启动时校验同一 URI/默认库指纹；浏览器只显示实例、SSH 目标、数据库主机、profile 和 `connectionStatus` 返回的数据库身份。

插件管理员身份只允许使用人工工作台，不授予 SSH 或数据库权限。数据库账户权限决定读写能力。用户可在 mongosh 主动切换库、认证或连接；此后须自行核对新目标，面板展示的是启动时核验的连接。任意 shell 写入不提供回滚保证。

## 结构化 GUI 与边界

`manual-mongodb.js` 创建独立 SSH transport，并在专用 exec channel 中运行 `manual-mongodb-runtime.js`。远端 Node 驱动保持单个 MongoClient、最多两个池连接和一个分页游标。GUI 数据来自有界 NDJSON 请求/响应协议，不解析交互式 shell 输出。MCP、自动 Worker、自动 `runSSH` 均不能进入该通道。

筛选使用 Extended JSON，返回与编辑使用 canonical Extended JSON、`relaxed: false`；驱动读取关闭数值提升，保留 ObjectId、Date、Decimal128、Int32、Long、Double、Binary 等 BSON 类型。缺少 EJSON 支持会明确拒绝 GUI 连接，不以普通 JSON 静默损失类型。

查询每页 1–100 项，默认 30；文档按指定排序附加 `_id` 作为稳定的次序字段。使用服务端游标而非高 offset 或无界 `toArray()`。目录和索引可继续分页；切换目录/查询会关闭旧游标，需要重新查询恢复文档分页。每页 EJSON 数据约 384 KiB、单文档 384 KiB 上限，超大文档转由 shell 处理。驱动批次仍受 MongoDB 的服务器批次边界约束；列库使用服务器的原子 `listDatabases` 元数据回复，再进行有界分页面向浏览器输出。

数据库查询 `maxTimeMS` 10 秒，连接选择/建连 10 秒，网络 socket 20 秒，本地单次请求 25 秒。远端辅助进程 90 秒无协议输入后清理；已连接工作台每 30 秒检查远端 profile 的 URI/默认库指纹，检查不续人工闲置期限。shell 使用第一阶段相同的渲染确认、暂停/恢复、高水位断开、输入速率限制与尺寸校验。

GUI 编辑只实现单文档 `replaceOne`：选中文档、编辑、准备计划、核对实例/身份/库/集合/动作、确认执行。计划绑定人工会话和连接 ID，60 秒有效且执行前一次性消耗。替换必须保留 `_id` 及 BSON 类型，不支持 upsert。原文档作为等值比较条件，若文档删除或发生不等值变化则拒绝覆盖。比较使用 MongoDB 文档等值语义（数值比较遵循数据库规则），不构成事务快照，也不能识别修改后恢复的 ABA 情形。MongoDB 4.4 通过 `objectToArray` 避免直接比较 `$$ROOT` 的旧优化器问题。

网络断开、超时或退出后不重试写入；操作者必须重新查询核对结果。GUI 未实现插入、删除、索引变更或任意 shell 操作的自动回滚。顶层 `$` 字段及超过 GUI 上限的文档需在 shell 中处理。

## 授权与生命周期

所有数据库 HTTP 请求要求有效人工 token、原实例配置指纹及工作台 Host/Origin。Manager/MCP token 不可替代人工 token。数据库 shell 票据与 SSH 票据分离、十秒有效、一次性使用，并额外绑定当前数据库连接 ID。旧连接不能向新目标提交查询、确认计划或连接票据。

数据库断开/重新连接清除文档、编辑内容、游标、计划及数据库 shell，同时保留独立 SSH 终端。远端 profile 变化会在下一次结构化请求、shell 启动或最长约 30 秒的周期检查中拒绝旧目标。实例编辑/禁用/删除、管理员密码恢复、退出、人工闲置/绝对超时和 Manager 关闭沿用第一阶段撤销规则，并清理所有数据库通道。请求返回前再次验证会话和连接，避免退出/切换后的旧结果回填页面。

数据库点击、查询、确认、编辑及终端键入计作人工输入；目录状态轮询、远端检查和输出不续闲置期限。15 分钟闲置、8 小时最长会话不变。审计仅增加连接/写入动作、连接 ID、命名空间及结果元数据，不记录文档内容、URI、终端字节或凭据。

## 依赖与验证

GUI 使用原生 DOM 与现有 xterm 6.0.0（MIT）；没有引入新的生产依赖或复制 Compass SSPL 组件。远端驱动、mongosh 由实例维护，插件不打包它们。隔离验证使用的 mongodb 6.21.0 与 mongosh 2.13.0 的已安装 package.json 均标注 Apache-2.0；仅临时安装于测试目录。维护成本为本项目的结构化协议、连接生命周期及 DOM 页面，不包含 Compass 的大型 UI/构建链。

使用明确的 Node 22.18–22.x 运行：

```sh
cd agent
npm run build:runtime
npm test
npm run test:manual-browser
# 仅对临时 loopback MongoDB；脚本主动拒绝非 loopback URI。
RDA_MANUAL_TEST_MONGO_URI='mongodb://临时管理员:临时密码@127.0.0.1:临时端口/admin?authSource=admin' \
RDA_MANUAL_TEST_DRIVER_PATH=/临时依赖/node_modules/mongodb \
RDA_MANUAL_TEST_MONGOSH_PATH=/临时依赖/node_modules/.bin/mongosh \
npm run test:manual-database
cd ../plugins/remote-debug-agent
npm test
npm run diagnose
```

可设置 `RDA_MANUAL_TEST_BUNDLED=1`，使用实际打包 Manager 内的工作台、静态资源和远端脚本再运行相同浏览器流程。

数据库集成脚本使用随机命名库、独立读写/只读账户、临时 registry/profile、真实 ssh2 服务器与 Python PTY、真实 Chromium / Node 驱动 / mongosh；完成后删除测试库/用户/临时文件并关闭连接。系统原生认证沿用第一阶段独立验收，本阶段自动化不触发原生认证弹窗。
